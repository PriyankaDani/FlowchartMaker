# Image parsing goes through a disposable text description, not direct structured extraction

Image input could go straight from sketch to structured `Flowchart` via a single vision-LLM call with structured output. Instead, the vision model's only job is to produce a free-form natural-language description of the sketch (the `Sketch description`), which is then fed through the *same* text-parsing chain used for typed input. We chose this because it gives both input paths a single shared extraction chain — one prompt to maintain, one prompt-injection defense point, one place the `Flowchart` schema is enforced — at the cost of a second LLM call (extra latency) for image input. A future reader tempted to collapse this into one vision call to save a round-trip should know the reuse and injection-defense properties were the point, not an oversight.
