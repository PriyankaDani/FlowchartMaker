# `VisionParsingChain`'s qualifying tests run against Gemini, not a local Ollama vision model

CLAUDE.md's TDD policy is that a ticket's tests run green against Ollama before closing, with the Gemini polish pass being a separate, non-blocking concern. `003_vision_parsing_chain` is an exception: its Ollama-integration tests (`tests/parsing/test_vision_chain_gemini.py`, despite the historical `_ollama.py`-style naming convention used by `002`) run against `gemini-2.5-flash`, not a locally-hosted vision model. The ticket's own exit condition already anticipated this: "Ollama's vision-capable model (**or a documented local equivalent**)" — this is that documented equivalent.

Three vision-capable models were tried locally on this machine before falling back to Gemini:

- **`llava` (7B)** and **`llava:13b`** load and run, but are unreliable in both directions: on a genuinely blank test image and a messy-scribble test image, both consistently returned an invented, plausible-sounding flowchart description instead of flagging the image as unreadable — regardless of whether the unreadable-check was combined with the description request or asked as a separate strict yes/no gate beforehand (the two framings gave contradictory answers on the *same* image). On a real sketch, `llava` (7B) also partially hallucinated a box that wasn't present. `llava:13b` was additionally too slow to return a result inside a 10-minute timeout on this hardware.
- **`llama3.2-vision`** fails to load at all: `error loading model: unknown model architecture: 'mllama'`, reproduced even after confirming the installed Ollama build (`v0.33.3`) was already the latest available release — this is a genuine gap in what this Ollama build's inference engine supports, not a stale-version problem.

Gemini (`gemini-2.5-flash`) was tried against the same three fixtures and got all three right on the first attempt: an accurate, non-hallucinated description of the clean sketch (every shape, label, and both branch labels), and a correctly-raised `SketchUnreadableError` for both the blank page and the messy scribble.

**Consequence — rate limits.** Unlike Ollama, Gemini's free tier is rate-limited (5 requests/minute, 250k tokens/minute, 20 requests/day at the time of writing) and the qualifying test suite consumes part of that daily budget every run. `test_vision_chain_gemini.py` is deliberately kept to exactly 3 tests, each making exactly one LLM call (matching the ticket's three fixture-driven exit conditions), so a full run costs 3 of the 20 daily requests. It should not be run more often than needed to verify a real change to `VisionParsingChain`, `prompts.py`'s vision prompt, or the fixtures themselves — not as part of routine full-suite runs. The fast, free unit tests in `test_vision_chain.py` (mocked LLM) remain the tests to run for everyday iteration.

A future reader who gets a usable local vision model working (a newer Ollama build with `mllama` support, a faster/more accurate small vision model, different hardware) should be able to restore the Ollama-first policy for this component by pointing `test_vision_chain_gemini.py` (or a reinstated `_ollama.py` sibling) at `LLMProvider()`'s default Ollama-configured `vision_chat_model` instead of an explicit `gemini` `Settings` override — the chain and prompt code make no assumption about which provider backs `vision_chat_model`.
